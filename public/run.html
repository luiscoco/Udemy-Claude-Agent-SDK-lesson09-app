Follow the summary, approval, precedence and turn-limit exercises in order.

01

Install the application

Use Node.js 24+, npm and your own model-accessible Anthropic key. Keep optional npm dependencies enabled so the SDK runtime is installed. Python is not required to run this TypeScript app.

cd .\agent-sdk\lesson09-options
npm ci
02

Create .env and start

Preserve an existing local file. Enter your own key, save and start. The script loads .env explicitly; existing shell variables take precedence.

if (!(Test-Path .env)) { Copy-Item .env.example .env }
notepad .env
npm start

Safe template:

ANTHROPIC_API_KEY=your_api_key
CLAUDE_MODEL=claude-sonnet-4-6
PORT=3109

Open http://127.0.0.1:3109. Keep the terminal open. Ctrl+C stops it; restart after configuration changes.

03

Compose the read-only agent

Keep the TODO summary selected with maxTurns 8, budget threshold $0.30 and low effort. Run it. Inspect model, cwd, tools, allowedTools, limits and [] settings in the option projection. Confirm TODO-101, TODO-102 and TODO-103 and an unchanged status file.

04

Prove that allowedTools does not restrict

Choose Only Read pre-approved · Edit available. Run once. Inspect Edit in system/init, the Edit request, the actual canUseTool allow decision, and status.txt changing from draft to reviewed. The callback is automatic and scoped to that file; no human approval is being simulated.

05

Test a project allow against a programmatic block

Choose Project allows Edit · options block it. The host selects project settings and explicitly disallows Edit. Inspect the loaded-source choice, the real project allow file, Edit missing from init, and the unchanged status file. This case demonstrates that particular block, not every possible precedence interaction.

06

Observe the one-turn limit

Choose TODO summary and set maxTurns to 1. Run and inspect error_max_turns. The SDK can yield a typed error then throw; the host preserves the result and still reads the actual file afterward. Restore 8 before the other exercises.

07

Use the terminal entry point

sample:env loads the optional local .env. sample uses only the inherited shell environment. Run browser and terminal experiments sequentially.

npm run sample:env -- summary 8
npm run sample:env -- approval 8
npm run sample:env -- blocked 8
npm run sample:env -- summary 1
npm test

Windows and runtime troubleshooting

If required, add CLAUDE_CODE_GIT_BASH_PATH=C:/Program Files/Git/bin/bash.exe only after verifying the installed path. A second start recognizes this app and prints its existing URL; choose another PORT for an unrelated listener. Check key and model access for provider errors. The expected one-turn limit is an SDK outcome, not a successful TODO summary.

If the approval callback does not appear or the file does not change, keep that actual result and inspect the log. An Edit request alone does not prove completion. The controlled fixtures reset at the start of each run; no user repository path can be submitted through the UI.
